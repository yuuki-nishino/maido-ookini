# ADR-0009: 在庫が足りないときは、選べば予約注文として確定する（在庫はマイナスにする）

- 状態: 採用（Accepted）
- 日付: 2026-10-19
- ADR-0008 の「足りなければ確定しない」を、一部変える（足りないと知らせたうえで、スタッフが選べば、予約として確定する）

## 背景

- ADR-0008（Issue #68）では、確定のときに在庫が足りなければ、何も書かずに止める（売りすぎない）
- 実際の運用では、在庫が切れても、補充が来れば作れる。そのときに、注文を断らずに「予約」として受けたい（Issue #69。ユーザーの要望）
- ユーザーの回答：予約は**普通の注文と同じ流れ**（調理中に入る。状態は増やさない）。予約にするのは**その場で選ぶ**。予約の数に**上限は設けない**が、**予約がいくつ入っているかを見て、人が決められる**ようにする。お客様画面で、予約であることを**伝える**

## 検討した選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| **A** | **在庫をマイナスにして、マイナスの分を「予約の数」とする。注文と行に、予約の印を付ける** | 在庫は「いまの残り」1つのまま（ADR-0008 と同じ形）。補充すれば、マイナスから埋まる。予約の数は、在庫を見ればわかる（別に数えない）。状態・遷移・ルールの変更が小さい |
| B | 予約を別に数える（`menu.reserved` など）。在庫は0で止める | 予約と在庫を分けて見せられる。ただし、補充のときに予約へ回す処理や、取り消しで戻す先が2つになり、複雑になる |
| C | 「在庫待ち」の状態を足し、補充したら「調理中」へ移す | 分かりやすいが、状態の遷移・ルール・調理画面が大きく変わる。ユーザーは「普通の注文と同じ流れ」を選んだ |

## 決定

A を採用する。

- **確定**：まず予約を許さずに確定する（ADR-0008 のとおり。足りなければ、何も書かずに止め、「在庫が足りない」と足りない商品を知らせる）。知らせの中の「**予約として確定する**」を押すと、同じカートで、予約を許して（`draft.reserve`）、新しい注文IDで確定し直す。このときは、足りない分も含めて在庫を減らし（マイナスになる）、足りなかった分を、その行の `reserved`（予約の数）にし、注文に `reserved: true` を付ける。「数を減らす」を押せば、これまでどおり確定しない
- **予約の数**：在庫のマイナスの分（残り −3 ＝ 予約 3）。メニュー画面・注文画面に出す。**上限は設けない**。受け付けを止めるときは、手で「売り切れ」にする
- **残り0以下の商品**：注文画面で**押せる**（予約で受ける）。#67 の「残り0は売り切れと同じ（押せない）」を変える。売り切れは、手の切り替えだけ
- **調理画面**：予約を含む注文のカードに「予約」の印、行に「（予約 N）」。流れは普通の注文と同じ（補充して作れるようになったら「完成」）。どの予約が満たされたかは追わない（人が見て決める）
- **お客様画面**：調理中で予約を含むとき、「在庫を用意しています。用意でき次第、調理します」を添える
- **取り消し**：ADR-0008 のとおり、確定で減らした数（予約の分を含む）を戻す
- **ルール**：注文の作成に `reserved`（任意の真偽値）を足す。作成のあとは変えられない

## 結果

- 在庫のマイナスは、「取り消しを戻す」で生じるもの（ADR-0008）と、予約で生じるものが、区別なく「予約の数」として見える。どちらも、補充で埋まる
- 予約の印は、補充したあとも残る（満たされたかを追わないため）
- お客様に渡す項目に `reserved` が加わる（個人の情報ではない）
